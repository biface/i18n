Corpus module¶

class i18n_tools.models.corpus.Corpus(domain: str)¶

Container of Books for a single domain across all loaded languages.

Corpus holds one real Book per available language. Its central entry point is get_book(lang), which returns a FallbackBook — a transparent proxy that resolves each message individually through the fallback chain (DD-09).

The fallback chain for a requested language lang is built inline (v0.3.x, no fallback.py yet) using the IETF parent tag extracted via langcodes. The full fallback.py module (DD-29) will replace this inline resolution in v1.0.0.

Cross-language operations¶

  • coverage() — coverage rate per language (0.0–1.0)

  • missing(lang) — identifiers absent in lang but present elsewhere

  • languages — list of loaded languages

  • check() — structure and token names of each message across languages

References

  • biface/i18n#43 : Corpus design (DD-09, DD-09b)

  • biface/i18n#20 : MessageNotFoundError (DD-24)

add_book(book: Book) → None¶

Register a real Book in this Corpus.

Parameters:

book (Book) – A fully populated Book whose domain matches this Corpus.

Raises:

  • TypeError – If book is not a Book instance.

  • ValueError – If the Book domain does not match the Corpus domain, or if a Book for that language is already registered.

References

  • biface/i18n#43 : Corpus design (DD-09)

get_real_book(lang: str) → Book¶

Return the actual registered Book for a language — no fallback resolution, unlike get_book(), which always returns a FallbackBook proxy. Useful for callers that need the concrete Book itself (e.g. saving it back to disk), rather than the resolved-content view.

Parameters:

lang (str) – Exact language tag to look up.

Returns:

The Book registered for that exact language.

Return type:

Book

Raises:

KeyError – If no Book is registered for that exact language — no fallback chain is consulted.

get_book(lang: str, repository: Repository | None = None) → FallbackBook¶

Return a FallbackBook for lang built from a fallback chain.

Two resolution modes:

  • repository supplied: the chain comes from fallback.resolve(lang, repository) — the requested language, its IETF parent, variants declared under that parent in repository.hierarchy, and the repository’s global fallback and its own variants — filtered to the languages actually loaded in this Corpus.

  • repository omitted: the inline heuristic chain (unchanged from prior versions), for a Corpus used standalone without a Repository at hand:

    1. The requested language, if loaded.

    2. The IETF parent tag (e.g. fr for fr-CH), if different and loaded.

    3. Any other loaded language whose IETF parent matches (siblings).

    4. All remaining loaded languages, in insertion order.

If the resulting chain is empty, MessageNotFoundError is raised.

Parameters:

  • lang (str) – Requested language tag (e.g. "fr-CH").

  • repository (Repository | None) – Optional Repository to resolve the chain against fallback.resolve() instead of the inline heuristic.

Returns:

A FallbackBook wrapping the resolved chain.

Return type:

FallbackBook

Raises:

MessageNotFoundError – If no loaded Book matches the chain.

property domain: str¶

The domain this Corpus covers.

property languages: list[str]¶

List of loaded language tags, in insertion order.

coverage() → dict[str, float]¶

Compute the coverage rate of each loaded language.

The reference set is the union of all message identifiers across all loaded Books. Coverage for a language is the fraction of reference identifiers present in its Book.

Returns:

Mapping of language tag to coverage rate (0.0–1.0). Returns an empty dict if no Books are loaded.

Return type:

dict[str, float]

check() → list[Finding]¶

Check that each message has the same structure and the same token names in every language.

The fallback chain resolves a whole message: a language holding the identifier answers with its own message, a language without it answers with the message of another language. Comparing the messages resolved for every language therefore amounts to comparing the messages of the same identifier held by the books. Only "complete" messages are compared: a "draft" takes part in the fallback chain but carries no integrity obligation.

Two complete messages of the same identifier must have the same number of declensions and of segments. When they do, each cell (variant, segment) must carry the same set of token names in both. The text of a cell is read after the column fallback, so an absent text is compared through the text that replaces it at publication. Token order and repetitions are not compared.

Each mismatch is reported with severity "error" and the identifier of the message. Nothing is raised and the books are not modified.

Returns:

The findings, by identifier; empty if nothing is wrong.

Return type:

list[Finding]
