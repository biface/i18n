4.5.3. Loader module¶

This module handles the file operations necessary for internationalization (i18n) tools. It focuses on loading and saving configuration files, managing .pot files for translation projects, and orchestrating repository-wide operations (scaffolding, archiving, aggregation, and translation-set CRUD).

Key Features:

  • Load and save configuration files in YAML, TOML, or JSON formats.

  • Search for configuration files in application directories.

  • Load and save .pot files, including metadata headers and translation entries.

  • Build, verify, archive, and restore a whole repository.

  • Add, update, remove, and aggregate translation sets across modules, domains, and languages.

loader.py is the sole bridge between /models/ and the rest of /loaders/ (DD-06, DD-NN). handler.py and utils.py must never be imported directly from /models/ — models talk only to this module, which can in turn be used standalone (returning raw dicts, no model objects required) or together with model instances (e.g. Book, Repository).

i18n_tools.loaders.loader.load_locale_json(file_path: str) → dict[str, Any]¶

This function load a JSON file in the locales repository and containing i18next data. The structure of this dictionary is as follows:

{
    "msgid_001": [
            ["msgstr_001_000", "msgstr_001_001"],
            ["msgplr_001_1_000", "msgplr_001_1_001"],
            ["msgplr_001_2_000", "msgplr_001_2_001"]
        ],
    "msgid_002": [
            ["msgstr_002_000"],
            ["msgplr_002_1_000"],
            ["msgplr_002_2_000"]
        ]
}
Parameters:

file_path (str) – Path to the JSON locale file.

Returns:

JSON locale data content.

Return type:

dict

Raises:

  • FileNotFoundError – If the file is not found.

  • ValueError – If the file is not a valid JSON or fails the integrity check.

i18n_tools.loaders.loader.load_book(file_path: str) → dict[str, Any]¶

Load a .i18t dictionary file and return its contents as a filtered dict (DD-15, DD-16, DD-34).

The serialisation format is detected from the file extension (DD-34), symmetrically to save_book(). The reserved keys .i18n_tools and metadata are silently ignored.

Parameters:

file_path (str) – Path to the .i18t translation file.

Returns:

Mapping of msgid to i18n_tools entry dict {"messages": matrix, "metadata": {}}.

Return type:

dict[str, Any]

Raises:

  • FileNotFoundError – If the file does not exist.

  • ValueError – If the file fails the integrity check.

i18n_tools.loaders.loader.save_book(book: Any, file_path: str) → None¶

Serialize a Book to a .i18t file.

The serialisation format (JSON or YAML) is detected from the file extension. The structure written to disk follows the native .i18t format:

{
    "metadata": { ... },
    "<msgid>": { "messages": [...], "metadata": { ... } },
    ...
}
Parameters:

  • book (Book) – The Book instance to persist.

  • file_path (str) – Full path (directory + filename) of the target .i18t file.

Raises:

FileNotFoundError – If the parent directory does not exist.

References

  • biface/i18n#42 : strict separation models / loaders (DD-06)

  • biface/i18n#46 : loader ↔ models bridge and native serialisation (DD-15, DD-16)

  • biface/i18n#56 : .i18t naming convention and format detection (DD-34)

  • biface/i18n#57 : Book.save() persistence

i18n_tools.loaders.loader.aggregate_locale_json(structure: dict[str, Any], domains: dict[str, list[str]], languages: dict[str, list[str]]) → dict[str, Any]¶

Aggregate JSON locale files based on the given structure, domains, and languages.

Distinct from aggregate_dictionaries(): this function works from generic, caller-supplied parameters (no Repository instance, no embedded metadata) and reads files directly from disk by path. Kept alongside it as a separate, legitimate responsibility — not a duplicate (DD-NN, #69).

Parameters:

  • structure (dict[str, Any]) – Dictionary containing ‘base’ path and list of ‘modules’.

  • domains (dict[str, list[str]]) – Dictionary where keys are module names and values are lists of domains.

  • languages (dict[str, list[str]]) – Dictionary where keys are language codes and values are lists of regional variants.

Returns:

A consolidated dictionary of locale data.

Return type:

dict

i18n_tools.loaders.loader.save_locale_json(file_path: str, data: dict[str, Any]) → None¶

Save data to a JSON locale file.

Parameters:

  • file_path (str) – Path to the JSON locale file.

  • data (dict) – Dictionary containing locale data.

Raises:

FileNotFoundError – If the directory for the file is not found.

i18n_tools.loaders.loader.save_aggregated_locale_json(aggregated_data: dict[str, Any], base_path: str) → None¶

Save the aggregated locale JSON data as gzipped files for each domain in the locales directory, and create a gzipped file for the entire module or sub-module at the base of its directory.

Companion to aggregate_locale_json() — see that function’s docstring for why it is kept distinct from aggregate_dictionaries() (DD-NN, #69).

Parameters:

  • aggregated_data (dict) – The aggregated dictionary of locale data.

  • base_path (str) – The base path where the locales directories are located.

i18n_tools.loaders.loader.build_book_filename(domain: str, fmt: Literal['json', 'yaml'] | None = None) → tuple[str, str]¶

Pass-through to i18n_tools.loaders.handler.build_book_filename().

Kept here so that Book (models/corpus.py) only ever talks to loader.py, consistent with the existing load_book/save_book pattern (DD-06, DD-08) — never directly to handler.py.

Parameters:

  • domain (str) – The translation domain name.

  • fmt (TranslationFileFormat | None) – The desired storage format (“json” or “yaml”). Defaults to “json” if None.

Returns:

A (format, filename) tuple.

Return type:

tuple[str, str]

Raises:

ValueError – If fmt is not a recognised translation format.
